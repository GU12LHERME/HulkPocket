# Hulk allocator stop checkpoint

RP6 watchdog captured a deliberate self-loop at guest 0008D320. The local generated USA function 00266E00 loads a type-indexed object at 00527C60 + type*16 and calls vtable slot +0xC; its normal return is 00266E1C. The guest source verifies the loop, but not the reason the object points to it. The runtime now intercepts that indirect target and logs the exact checked guest frame, allocator type and byte count, caller, object/vtable and recent kernel calls. It deliberately stops without returning fake memory. The local script summarizes original disassembly comments for the caller and bounded references to the table; the game remains local and cached objects unchanged. The hardcoded inspection addresses are USA trace-specific; only the verified return layout is decoded. Tests cover a non-returning diagnostic and the report parser. No allocator replacement or actual game fix is claimed yet.
