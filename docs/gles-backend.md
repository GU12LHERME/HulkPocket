# First Android GLES renderer slice

Chosen OpenGL ES 3 for a low-dependency first rendering checkpoint, not a final backend decision. Uses EGL pbuffer and actual GL shader compilation, clear, vertex upload, triangle draw and indexed draw via the portable D3D8 bridge, pixel readback and synchronous fences. Linux Mesa exercises real GL calls via software rendering, and CI separately compiles an Android AArch64 binary against NDK EGL/GLES libraries. Android execution remains a separate device gate.

Strict scope: one matching linear A8R8G8B8 surface, untextured pretransformed XYZRHW + diffuse triangle lists and default state. No Xbox shader translation, textures, guest depth/stencil, blending, surface copies, guest readback, window, GPU timing, or real game hooks yet. The shader is an original minimal diagnostic shader, not the game's shader. Unsupported operations stop explicitly. The context and backend must be created, used and destroyed on the same owner thread. No changes to private game code or recompilation cache.

Next gates: run the standalone diagnostic on physical Android; expand resource mapping, shader translation, render states and actual presentation; bind game-specific D3D8 HLE overrides after the device layout and ABI are verified.

## Texture slice
Stage 0 now supports explicitly configured SELECTARG1 or MODULATE color and select/modulate alpha on XYZRHW+diffuse+UV vertices. It decodes linear/swizzled BGRA textures using the portable Xbox converter, converts to RGBA for GLES, and provides a CPU BC1/2/3 fallback to avoid requiring S3TC driver extensions. Point/linear filtering and wrap/mirror/clamp are supported. It reuploads every draw to avoid stale data until guest locks and dirty epochs are connected; this is intentionally not the final performance path. Tests cover four differently colored texels, a rewrite at the same address, linear interpolation, a DXT1 draw, and BC2/3 alpha. Palette resource mapping, mipmaps, cube/volume textures, multitexturing, render-target synchronization, and programmable shaders remain unsupported. The previous untextured diagnostic remains in the same test.

## Depth, blending, transforms slice
Supports one matching linear D24S8 depth target mapped to EGL depth storage, requiring an explicit clear before depth-tested draws. Xbox GL-valued compare functions and a bounded set of blend factors/equations, ARGB color masks, and row-vector world/view/projection transforms are now mapped to GLES. Fixed-function XYZ+diffuse is supported alongside XYZRHW; clip depth is converted from D3D [0,w] to GLES [-w,w]. Pixel tests cover occlusion, disabled depth writes, alpha compositing, per-channel writes, and a transformed world-space triangle. The bridge's identity transforms and color mask are standalone defaults, not an emulated XDK device. Stencil, multiple targets, render target readback, lighting, programmable shaders and real game hooks are still pending. No private cache invalidation.
