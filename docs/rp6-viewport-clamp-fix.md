# Root fix for the original viewport clamp

RP6 c9ab8ff confirmed the first call to original SetViewport (0037F720, caller 0032156E) receives X=Y=0, W=640, H=480, MinZ=0, MaxZ=1, but returns zero W/H. Both CDevice+0x954 and +0x958 are zero. The original body loads the scaled right/bottom limits at 0037F838 and 0037F88C, clamps and divides by unit supersample factors, and stores the resulting W/H at 0037F8EA and 0037F8DE. Initialize those limit fields from the allocated framebuffer size, not hardcoded resolution or a patch to original code. Tests cover 640x480 and 320x240. The original 924 white pixels are independently confirmed in the exported BMP (640x480). The reduced unlit/untextured line replay now accepts a populated full-size guest viewport and preserves state; partial extents still reject. For local diagnosis only, HULK_CONTINUE_DRAW=1 allows one successful reduced draw at the observed USA caller and exact original 1020-vertex count to return after pixel readback, with stack ABI checked. Normal full draw guards, unknown commands and swap checkpoints remain. This is not full raster fidelity or a playable frame. CI and RP6 validation pending.
