# NV2A state execution and color readback

Follow-up to validated bc26f6a. Device memory now has a real 64 KiB physically backed XDK scratch buffer and threshold (upstream ScratchPush). The bridge consumes checked method packets, applying a transactional subset of simple render states and vertex constant load/data methods with a persistent cursor. Unsupported methods reject the entire state batch; immediate draws, texture and report commands still require implementations. GLES copies the single current linear A8R8G8B8 framebuffer back to guest BGRA with pitch and row orientation; no depth, async readback or general Sync yet. The live CreateDevice probe exercises allocated scratch, method decoding, real clear and guest memory readback, present and rotation, while deliberately stopping before guest defaults. Tests cover split constants, rejection without partial state, scratch pointer and actual color readback. Real game draw and live device initialization remain unvalidated. No changes to generated code.
