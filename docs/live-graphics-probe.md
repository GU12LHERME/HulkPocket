# Live Direct3D device checkpoint

Generated D3D_Device and D3D_pDevice symbols are now forwarded by the real strong CreateDevice override. The local diagnostic builds the real EGL/GLES backend, and if the game reaches CreateDevice, allocates actual guest buffers using its presentation parameters, binds them to the bridge, clears a diagnostic color, verifies RGBA readback, presents and rotates guest buffers. All graphics allocations are released on the same caller thread. It deliberately stops after the probe: this is not a game-rendered frame and does not return an incomplete device. Unsupported formats/MSAA are rejected. CI exercises the same probe against Mesa and builds the full Android ARM64 diagnostic. The new NV2A scratch method decoder supports checked increasing/non-increasing packets, rejects malformed packets, unsupported subchannels and control flow, and has synthetic tests. It is not yet a full pushbuffer executor. Remaining device work includes guest default states, method execution, resource references, shader/state mirrors and actual guest draw integration. No game assets or generated objects changed. CI and RP6 validation pending.
