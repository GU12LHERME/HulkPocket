# Guest clock and watchdog checkpoint

RP6 revision 2c86b01 passed MmQueryStatistics twice and was stopped by signal 14 (the existing 15-second watchdog). The exact stalled instruction was not captured. The prior runtime advanced KeTickCount only on kernel calls, so a CPU-only polling loop could remain stuck. Start a joined clock pump in the diagnostic session after fork, updating the aligned tick DWORD with an atomic store. This does not prove the actual game loop polls that export, and cached guest loads are not changed. The watchdog now reports PC, recent kernel return address, thread and ARM64 registers. Main join and clock pump block SIGALRM to favor a running guest worker; in multithreaded execution the chosen worker is not necessarily the culprit. The watchdog limit remains unchanged. Tests exercise tick progress without a kernel call and SIGALRM diagnostic output. No generated game objects changed.
